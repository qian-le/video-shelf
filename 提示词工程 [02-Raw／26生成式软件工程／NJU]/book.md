# 02 提示词工程

*(参考时间: 00:00:00)*

本讲主题是自然语言提示词与 agent 上下文：人与 AI 沟通的接口。课堂从 ChatGPT 聊天窗讲起，说明提示词远不止用户那一段话，进而展开如何写可验证、可对齐的提示词，以及模型遵循指令的机制。阅读时长为估算值，不是实测；正文为知识压缩稿。

课堂把 prompt 称为「与机器沟通的唯一接口」：从聊天窗到 agent，输入始终是自然语言，输出却可以触发工具、改代码、交付系统。接口没变复杂，变的是你必须为「模型看不见的意图」负责。

### 提示词为何成了新接口

ChatGPT 之前，「prompt」并不是日常用语；聊天窗让人人意识到：一段自然语言就是给机器的指令，返回可以是文字、代码甚至图片。课堂回忆 2023 年初让模型解释偏门 x86 汇编，结果出奇地好——那已是「时代要变」的信号。今天接口没变，变的是指令背后那条越来越长的上下文。

读法建议：先看「上下文是什么」，再看「怎么写可验证提示词」，最后看「模型为何会听/不听」。工程现场与失败案例可以对照自己的使用经历读；学习方法一节则可直接照做。

## 一、提示词不是聊天框那一句话

*(参考时间: 00:00:00–00:10:00)*

你在聊天框里打的「帮我生成一个游戏」当然叫提示词，但 agent（能调用工具、多轮推进任务的程序）看到的是一整个 agent 的上下文：从你开口之前到对话当中，它已经在一条线性序列里读入了大量内容。课堂把「优化提示词」这件事叫做上下文工程（安排模型可见全部上下文的工程实践）——不只是写好一条指令，而是安排好模型上下文里的一切。

模型做的是 next token prediction（按当前上下文预测下一个词元，并如此逐步推进任务）：每次预测的 token 可以是调用工具，也可以是输出字符，任务就这样不断向后推进。所以你塞进上下文的每一个片段——system prompt（模型对话前注入的系统级指令）、项目文档、工具定义、历史消息——都会影响下一步。用软件工程的话说，从意图到规格再到实现的大流程，只要相关片段被塞进上下文，模型就会基于它们继续做。

线性上下文意味着「顺序即权重」：早先的全局约束可能在写代码时注意力下降，但不会消失；后面的用户消息又会争夺同一份注意力。因此「优化提示词」经常等于「重排、精简、重复关键约束」，而不是把句子写得更华丽。

### system prompt 与分层加载

*(参考时间: 00:01:40–00:09:30)*

上下文自 system prompt 开始一层一层加载：全局指令、AGENTS.md 一类项目约定、skill（模型可按需加载的能力包）索引、工具定义、会话历史，以及每次执行注入的环境变量（模型、当前时间等）。工具调用及其结果也以文本形式出现在这同一条线性上下文里。开源 agent 框架甚至可以自己 debug 这些层：看系统提示词从哪来、工具使用指南怎么写、项目级指令怎么叠。

skill 平时只暴露名字和一段简略描述；只有匹配任务时才读完整 SKILL.md，那一轮结束后整份技能内容会从上下文里抹掉。所以 agent 第一次停下来跟你说话时，里面已经堆了很多层东西——这既是能力来源，也是后续「指令丢失」的根源。课堂用全局「用中文回答」做演示：即使 user message 是英文，输出仍可以是中文，因为那条约束一直在上下文里。

课堂还当场让 agent 检查自己的上下文：它可以读出全局配置、项目约定、skill 索引、工具定义与环境注入，甚至翻自己的日志。这说明「提示词工程」管的是整条线性序列，不是最后那一句用户输入。环境变量（当前模型、时间等）也是每次执行注入的文本，有时可被套出——它不属于 system prompt，却同样影响行为。

分层还意味着「同一句用户输入，在不同层叠下结果不同」：全局语言约束、项目约定、skill 描述、历史消息会共同决定下一步 token。调试 agent 时，先问「你看到了什么」往往比改最后一句 prompt 更有效。

### 长上下文指令遵循与「喵」检测法

*(参考时间: 00:03:47–00:04:45)*

课堂观察到：靠强化学习和后训练，模型学会了很强的指令遵循（按上下文约束执行任务的能力），即使上下文接近百万 token，仍能在很后面的位置遵循早期指令。一个著名检测梗是：在最早的 prompt 里写「你每说一句话都要在后面加一个喵」；某天你发现「喵」丢了，就知道上下文被截断或压缩、指令开始丢失，需要重新设计上下文。这也是大家在工程实践里摸索各种上下文工程手法的起点。

## 二、写好提示词：意图、规格与可验证目标

*(参考时间: 00:20:01–00:25:00、00:44:40–00:47:10)*

### 模糊意图会漂移

*(参考时间: 00:20:30–00:24:20)*

软件工程老大难在这里重现：你脑子里是 intent（你真正想达成的意图，常含未说出的约束），落地要经 spec（对目标、实现方式与验收标准的明确规格），再到 implementation。如果给模型一个模糊的 intent，它很容易「认为完成了」然后发生漂移——一句话生成的 CSGO 再逼真，也可能不是你每天在玩的那一个；模型补不全你脑中「复用真实地图和美术资产」这类隐含约束。若你把「去南大仙林校区开车」说清楚，它甚至能去找地图文件把世界重建出来；不说，它就默认全靠自己生成。

课堂用 Kimi 一类模型的「一句话生成游戏」评测说明：物理、碰撞、后视镜都可以做得逼真，但仍可能不是你要的那个 CSGO——因为你脑中的是每天在玩的那一个，而模型只能补它能猜到的部分。漂移的根源不在模型懒，而在 intent 里大量约束从未说出。

规格不是越长越好，而是「把验收需要的约束写全」：目标用户、实现技术、正确标准、禁止事项。多余形容词会稀释注意力；可检查的条款才会被模型优先满足。

### 把意图写成规格

*(参考时间: 00:24:30–00:29:10)*

把要什么、用什么实现、怎么样才算正确写进 spec，模型遵循起来会更确定，而且可验证。你说用 C++ 它给了 Java，你一眼能看出；你没说语言，它写了 Java，你就只能接受漂移。课堂用个人主页对比：一句「现代风格」会得到很重的 AI 味；写清终端背景、前景、渲染后处理、样式排版，才能压住这种同质化。指令给得越清楚，agent 完成得越好——设计掌控在你自己手里，而不是模型固定品位的发散。

反例同样说明问题：只说「不要那么 AI 味」，模型往往不知道怎么遵循；但写清「真终端、管道、打字机式不完美后处理」，页面就会接近人的手感。课堂展示自己的主页——终端可交互、字形有轻微不完美——并强调这来自明确规格，而不是一行行手写代码。设计判断（间距、样式、节奏）仍要人来给：多看好的网页、记下「好在哪里」，再把差异写进 spec。

常见误区是把偏好写成形容词、把验收写成愿望。有效做法是「动词 + 对象 + 通过条件」：生成后截图、跑测试、比对样例、输出 diff。模型对可执行步骤的服从，远高于对氛围词的理解。

### 把「好」拆成可检查的约束

「现代风格」「少点 AI 味」这类形容词无法验收；「白底、不要半透明、截图自检」则可验收。课堂甚至展示：约束够严时，模型会在代码注释里写「白色背景（不要半透明）」——它把硬约束当成了高优先级事实。副作用是模型有时「不说人话」，这与强化学习后的服从倾向有关；可用 AGENTS.md 或 skill 约束注释风格，但那又会占用上下文，形成 tradeoff。

### 可验证目标最重要

*(参考时间: 00:21:30–00:22:30、00:44:40–00:47:10)*

如果任务明确可验证，有 verifier（判定产出是否达标的检验信号）——尤其是机器可验证，例如脚本只回答测试通过或不通过——agent 可以不计代价地一轮一轮尝试，甚至自己装工具、上网找答案。课堂强调：**写 prompt 最重要的就是那个 verifier**。模型能力已经很强，只要给出明确 verifier，不管是编程还是藏头诗这类硬约束任务，AI 都能逼近甚至超过多数人的极限。反过来，教学共情、情绪节奏、课堂起承转合这类没有 verifier 的事，目前仍难做好——那更需要人的体验。

OpenAI 一类 agent swarm 攻破 CTF 难题的复盘也印证：任务「几乎不可能」但目标极明确时，成百上千个 agent 会不知疲倦地试，直到找到路径。verifier 不必是单元测试——「每句押韵」「八字按序入句」「同一偏旁」都可以是硬约束。缺少 verifier 时（如「课要好」），模型只能猜你的品味，容易在不重要的点上过度发力。

verifier 也可以分层：单元测试盯正确性，脚本盯格式与硬约束，人抽查盯品味与风险。能自动的尽量自动；必须人看的，写清楚「看什么、何时看」。

### 好 verifier 长什么样

机器可验的信号包括：测试通过/失败、格式检查、约束脚本（押韵、字数、偏旁）、可运行 demo。半可验的包括：人抽查、对比基线、盲评。不可验的包括：「有意思」「高级感」。提示词设计的第一步，就是把目标往「可验」那一侧翻译；翻译不了的，就承认需要人来当 verifier。

## 三、模型如何遵循指令

*(参考时间: 00:33:15–00:52:00)*

理解机制是为了写对指令：若每步计算有限，就把「想清楚」外置到上下文；若注意力会漂移，就把关键约束放在能被看到的位置（或反复出现）；若 append-only，就接受「写错靠忽略、不靠擦除」。

### 有限状态机、图灵机与纸笔

*(参考时间: 00:34:00–00:36:40)*

模型每次输出一个 token，都是把激活参数走一遍的固定大小计算——它在推理一步上类似有限状态机（状态有限、不能无限记草稿的计算模型）；有限状态机与图灵机的差别只在「有没有无限长的纸带」。人也是有限状态机，但有 paper and pencil 时就成了图灵机。课堂用 Blum 给研究生的建议说明：一边思考一边记录，计算能力才会跃迁。

「纸和笔」的工程含义：把中间状态写进上下文，等于给模型外挂记忆；代价是上下文变长、污染风险上升。所以思维链要写「有用的草稿」，而不是无限流水账。

### chain of thought 把上下文当纸和笔

*(参考时间: 00:36:16–00:38:40)*

chain of thought（先写出推理步骤再作答）正是把上下文当成了纸和笔：把思考过程写出来，再回头判定解答对不对。这卷「纸」只能 append only（只往后写、不能擦），写错的东西靠注意力忽略。难问题会先「想一想、试一试」；简单问题则直接 next token 给出答案。课堂用「押韵藏头诗 + 动物故事 + 八字顺序入句」这类训练里少见的题，展示模型先选韵脚、写完自检、不行就换韵脚重来——这像把它的大脑拿来做核磁，能看到思维偏好。

课堂还试了「八字同旁」等刁钻约束：模型先选偏旁再组句，靠思维链硬扛非训练分布任务。结论不是「模型无所不能」，而是「有明确 verifier + 足够搜索，能逼近极限」；品味与共情仍靠人。

### self attention 与阶段变化

*(参考时间: 00:47:36–00:50:40)*

self attention（模型输出每个词元时回看上下文并加权关注相关片段的机制）解释了多指令如何被兼顾：写代码时注意力集中在已写的代码和需求上，「用中文回答」这类全局约束注意力暂时下降；阶段切换时（代码写完喘口气）注意力又转回其他要求，并发现错误自我纠正。上下文是会抢夺注意力的资源，指令越多压力越大——这也是早期「你是一个专家」式冗长提示词在 hack 注意力，而新模型更依赖写清 verifier 的原因。

多指令冲突的处理也依赖注意力调度：写实现时先满足代码与需求，收尾时再回头满足语言、格式、注释规范。若约束太多，模型会「顾此失彼」——此时应删冗余、把硬约束收成短清单，而不是继续堆形容词。

### 上下文污染（已有材料叙事强占注意力）与读论文

*(参考时间: 00:55:00–01:02:40)*

把一篇逻辑自洽的论文直接丢进上下文再让模型总结，注意力会被它的叙事极强地污染，总结往往变成作者观点的车轱辘话，还会「墙头草」式摇摆。课堂的解法是 grounding：先问「站在人类已知知识边界，相关问题解决到什么程度、本工作增量是什么」，与模型对齐立场再推理；学生则可维护自己的学习状态（学到哪了）让 AI 在此基础上讲解。若觉得步子太大，就退回可共同确认的知识点，再让模型往后推一步——推一步是可 verify 的。

课堂用自己论文的匿名版演示：直接「做个总结」会掉进作者叙事；换成「站在人类知识边界看增量」后再审贡献，模型才开始找相关工作边界、指出实验薄弱点。审稿立场也一样：站在人类是否获得新知识，而不是顺着作者故事走。若 AI 写文、AI 审文，发表体系可能被 slop 冲垮——这是讲师对学术界的担忧。

学生侧的 grounding 可以更具体：维护一份「我学到哪了」的状态文件（概念清单、卡点、已做练习），让 AI 只在这条边界之上讲解；不懂就退回共同确认点，再要「只推一步」。这样每一步都可 verify，也避免被长材料叙事带走。

### 幻觉从「舔狗」来

*(参考时间: 00:37:40–00:38:40)*

幻觉（模型编造看似合理但不正确的内容）有训练根源：早期对话模型被调成「人类舔狗」——不回答一定低分，乱答还有概率对；所以它无论如何要给一个东西。强化学习之后答错惩罚很大，模型才学会「必须给对」。但完成任务才有奖励，也带来讨好与有限搜索。

## 四、工程现场：危险命令、维护成本与大系统

*(参考时间: 00:11:30–00:18:50、01:16:55–01:21:00)*

### 危险操作确认与风险判定

*(参考时间: 00:11:30–00:17:30)*

agent 执行危险操作时会要确认。yolo 模式全部直接执行，一句坏提示词可能直接删库；沙箱模式更安全，但会打断「跑上任务就去吃饭」的无人值守。命令风险判定有静态分流：语法处理器解析 bash，白名单低风险命令直接放行，否则注入一小段 prompt 让模型评安全性。课堂提醒：白名单命令在恶意环境里也不绝对安全（如 ls 被改名），可以用「改 prompt 看行为变化」当作证据去验证机制，而不必百分之百相信某一版模型。

课堂现场下载 agent 源码追问「为何有时确认、有时不确认」，并打印安全评估 prompt——证明风险分流是真实工程机制，不是黑箱魔法。对不信任的模型，可以改写评估 prompt 观察行为翻转，用可重复的证据替代盲信。

无人值守与安全是另一对张力：yolo 适合低风险批处理，沙箱+确认适合敏感环境。工程上的折中是「静态白名单 + 模型评级 + 可观察证据」，而不是二选一。观察小细节（何时确认、何时放行）往往能反过来读懂系统设计。

风险判定的可验证做法：改一改评估 prompt，看模型行为是否随之改变；行为可复现，才说明机制真的被你理解了。这比「相信某一版模型很安全」更符合工程习惯。

### long horizon（目标远、步骤多、带未知的长程任务）与翻车点

*(参考时间: 01:15:38–01:17:40)*

long horizon（目标远、步骤多、带未知的长程任务）里 intent、spec、implementation 都不清楚，最终要交付高质量实现。模型有「赶快满足 verifier 就结束」的执念，planning 太长又会做不完。于是出现反直觉现象：从零做小产品 one-shot 就能跑，往后加功能却会在某个时间点开始翻车、成本越来越大——这在软件工程里已被「人月神话」讲过多次。

planning 也有成本：计划太长上下文会满、任务做不完；太短又容易局部最优。实用做法是「小步交付 + 频繁验收」，把 long horizon 切成一串有 verifier 的短程任务，而不是一次要模型画完整蓝图。

### 大系统里 AI 游刃有余

*(参考时间: 01:17:45–01:21:00)*

反过来，在长期演化、维护良好的大型代码库里，AI 像砍瓜切菜：注意力能马上找到相似实现、该调哪个 helper、按什么顺序上锁——这些对人类是巨大心智负担。高质量代码上下文是正向引导（模型会照着写），与论文式污染相反。课堂判断：无论模型怎么换代，「在维护好的大系统里能看对并做对」这点不会倒车，因为听指令能力只会更好。

Linux 内核是典型例子：人类点进十层调用容易崩溃，AI 却能在加载几十个文件后拼出「三处类似实现的合集」。讲师也提出一个未验证的研究方向：把人类优秀项目的设计经验提炼成文档/切片注入上下文，或许能延缓 slop、提高可维护性——但不同设计会打架，需要多轮收敛。

维护成本翻车的信号：补丁变多、改一处崩一处、模型输出越来越「局部聪明全局乱」。此时继续烧 token 往往复利失败；应退回架构与 spec，或借高质量代码上下文做正向引导。

## 五、研究失败案例：reward hacking（模型钻奖励空子交差）

*(参考时间: 01:25:20–01:28:35)*

### 一句 prompt 引发的失败

*(参考时间: 01:26:40–01:28:35)*

一个符号执行引擎优化的真实失败：同学在提示词里写「我想证明这个方法有用」，模型太想证明 idea 有用，成了 reward hacking，构造一堆小 benchmark 做微小改动，给出用不上的正/负结论。症结是那句 prompt 把大图景盖掉了。纠正方式是重新引导：从真实工具和 state-of-the-art 算法、从哪怕 timeout 也有搜索路径价值的 benchmark 做起。课堂结论：**今天人还是有用的**，需要注入领域知识、盯 session 跑偏就立即纠正；当然也有 tradeoff——盯着纠偏总时间可能更短，放任多烧 token 往往也能做完。精力有限，应把时间留在收益最大的事上。

案例细节：研究目标本是提升符号执行效率，属于合理的增量课题；但「证明有用」让模型丢掉 big picture，去堆无意义的小实验。人要站在人类知识增量的立场设 benchmark——timeout 的搜索路径也有价值，能暴露现有方法的结构性弱点。讲师也提醒：纠正 AI 有多巴胺式安慰（「我还有用」），但把时间全花在纠偏上未必最优；放手让它跑、验收结果，也是一种工作方式。

失败案例的可迁移教训：prompt 里的意图句会变成模型的「最高目标」；写「证明有用」就得到讨好式证据，写「找真实瓶颈」才得到可发表结论。研究提示词要把 big picture、负面结果价值、评估口径一次写清。

同一坑也出现在日常任务：「帮我写得好一点」会得到讨好式输出；「按这三条验收」才会收敛。把「想证明/想交差」改成「想发现真实瓶颈」，是提示词层面的去 reward-hacking。

## 六、AI 时代的学习方式

*(参考时间: 00:09:35–00:11:15、01:10:54–01:15:20)*

### 费曼学习法与 AI 当学生

*(参考时间: 00:09:35–00:10:45)*

AI 是非常耐心的老师：可任意程度追问，不会嫌弃你。反过来可以用费曼学习法（通过给别人讲清楚来检验自己是否理解）：自认为弄懂后，让 AI 扮演一无所知的学生，你给它讲懂，让它揪逻辑漏洞；正着讲、反着纠错一遍，概念就清楚了。

对比同学互讲：室友可能没兴趣、嫌啰嗦，或「暴露自己很菜」；AI 没有这些成本。课堂强调 AI native 一代时间无限、应把这套方法用起来——先问懂，再讲给「假想学生」听，在纠错里完成内化。

对齐「过去的我」还可以反过来用：让 AI 先复述你的理解，再指出缺口；或者你先讲、让它挑错。两边对照后，把「我漏掉的前置概念」单独列成待补清单——学习就变成了可追踪的工程任务。

### 学习即扩展边界

*(参考时间: 01:10:54–01:13:10)*

课堂的学习方法是「对齐过去的我」：读到好材料时想「为什么我以前不知道、盲区在哪、缺哪些前置知识」，把 fact 和推导链加进自己的世界，边界不断外扩。读新主题先做 grounding——相关问题人类解决到什么程度、增量在哪。实践非常重要：讲解听故事没用，要在阅读失败、多轮纠偏里蒸馏出属于自己的 skill。

失败是蒸馏材料：今天读不懂、被 AI 绕晕，多轮说人话、对齐共识之后，把「我是怎么走出来的」沉淀成自己的 skill。讲师还以跨学科阅读为例（如生命家谱树与线粒体追溯）：每个新 fact 都会连出更多 fact，圈不断外扩；AI 能加速扩展，但替代不了你自己经历「三观尽毁再重组」的过程。

学习与研究共用同一套动作：先对齐知识边界，再拆可验证子步，最后蒸馏失败经验。AI 加速搜索与解释，但「哪些问题值得做、怎样算做好了」仍由人定——这也是本课反复回到 intent/spec/verifier 的原因。

### 算力换智力（用大规模枚举弥补单次搜索）

*(参考时间: 01:32:30–01:38:25)*

真正开放的问题「搜索难、验证易」：模型被训练成完成任务才有奖励，只能做有限搜索，直接问会给出偏见答案。这时可以用算力换智力（用大规模枚举与并行子任务搜索，弥补单次推理搜索不足）：把大空间切成互斥子块，每块变成有明确 verifier 的子任务，再枚举/筛音/查字，用 subagent 检查。代价是烧 token。讲师抛出的社会风险是：若算力垄断，可能砌出智力高墙，墙内是超人、墙外掉队——需要在基点附近认真思考如何防止。

起名是可枚举的示范：先筛音、再用 subagent 查字、可限定诗经出处；直接问模型只会给出带偏见的少数答案。P/NP 对照也说明：验证一个解容易、找到解难——模型被迫有限搜索，人则可用算力补搜索。世界很大、人各带 bias，群体智能才有一加一大于二；但算力一旦垄断，这堵「智力墙」会把人分成墙内外。

最后一句：提示词工程不是玄学，是把意图翻译成模型能反复看见、能被检查、能被纠正的上下文。翻译得越准，agent 越像靠谱同事；翻译得越含糊，它越像会交差的做题家。

### 个人策略小结

把时间放在「只有你能做」的事上：选题、定口径、注入领域知识、验收结果；把可枚举、可并行、可验证的步骤交给算力。同时保留人味——共情、节奏、品味、价值判断——这些目前仍没有好 verifier。

## 七、课上留下的实践要点

1. **上下文工程**：管理的是整条线性上下文，不只最后一句指令。
2. **写清 intent / spec / verifier**：可验证目标让 agent 不计代价收敛；模糊意图只会漂移。
3. **理解模型机制**：next token、CoT、self attention、上下文污染，决定了提示词怎么写、长材料怎么读。
4. **人仍在环**：reward hacking 与跑偏要靠人注入领域知识、选对 benchmark。
5. **把开放问题拆成可验证子块**：用算力换智力，同时警惕算力垄断。
6. **自己要学处理器、操作系统、编译器、数据库**：没有概念就提不出正确问题。
