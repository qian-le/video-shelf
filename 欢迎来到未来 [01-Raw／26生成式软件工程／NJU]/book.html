    本讲是开篇：从计算机史上的「能力日用品化」讲到 AI 时代的焦虑与机遇，再落到生成式软件工程真正要解决的问题——意图、规格与实现之间的 gap。阅读时长为估算值，不是实测。全篇按知识逻辑组织，不按课堂发言顺序；时间锚点可回看原视频。

    一、交叉路口：昂贵能力如何变成日用品

    (参考时间: 00:00:10–00:02:05)

    计算机发展史上多次重要变革的主线是把昂贵的能力变成了日用品：1975 年第一台 PC，互联网连接所有人，移动互联网一夜之间让菜场摊主也挂上收款码，再到 2022 年 ChatGPT——课堂称其为人类历史上增长最快的产品。站在这个交叉路口，上课方式与「该学什么」都需要重新思考。

    为什么这是一条主线而不是四件新闻

    课堂把 PC、互联网、移动互联网、ChatGPT 并置，用意不是罗列年份，而是指出「昂贵能力 → 日用品」的重复模式：计算、连接、移动接入、生成与推理，一次比一次接近人的日常。每一次普及都重写了「谁能做到、以什么成本做到」。对 computer science 学生来说，识别这条主线比记住某一年的机型更重要——它决定你该把精力放在哪。课堂语气是松散讨论，但结论很硬：站在交叉路口，上课方式与学习路径都必须重想。

    普及链条上的四次跳跃

    1975 年出现第一台个人电脑（课堂配图是 Altair 8800 一类的早期机型），把此前只属于机构的计算能力搬进个人桌面。随后互联网把所有人连在一起：讲师回忆自己小学快毕业时装过 ICQ，后来腾讯的山寨版还叫 OICQ，再改成 QQ；那时可以随机加上世界另一端的人，对方是英语母语者、打字极快，自己只会 hello 和 Good morning，完全接不上话——普及并不等于立刻用得好，但「谁都能连上」这件事本身已经改写社会。再往后是移动互联网：一夜之间菜场卖菜的人都有支付宝和微信两个二维码，在很短时间内改变了支付与生活方式。到 2022 年则是 ChatGPT，课堂称其为人类历史上增长最快的产品。

    对比也很重要：互联网刚普及时，语言与文化隔阂仍在；移动支付普及时，一夜之间改变了摊主的收款方式；ChatGPT 普及时，改变的是「谁会写、谁会想、谁会做」。每一次普及都留下新的不平等——不是能不能用，而是用得多深、用得多对。

    这四步不是孤立事件，而是同一条主线的连续展开——每一轮都把某种昂贵、稀缺的能力变成人人可及的日用品。对计算机专业的学生来说，判断「现在站在哪」很重要：你们是 computer science 的同学，进校时就该看到这条历史线。因此「该学什么、怎么上课」必须按这条主线重新思考，而不是沿用上一代的稀缺逻辑。课堂把这称为「人类命运的交叉路口」：上课方式、该学什么，都值得重新想一遍。

    二、「AI 替我上大学」与两种焦虑

    (参考时间: 00:02:15–00:06:30)

    课堂引用流行说法「AI 替我上大学」，并指出闭环里的致命点：只有学生没有受到训练。老师用豆包出题，大家用豆包做作业；操作系统作业可以直接丢进 codex，「蒋老师的操作系统课第八个实验」一句话就能代做。过去操作系统作业曾折磨大家，人在痛苦中获得提升；现在连复制粘贴都不必，把链接丢进去、甚至只说实验名，任务就结束了。讲师承认「答案既应该也不应该学」：有些能力仍需要，但具体怎么做还在摸索；正是在这种普遍焦虑下，才决定开这门 web coding 的课。

    由此产生两种焦虑：

    1. 每门课都很好、开卷全是 AI 答题，出来却发现自己第一个被 AI 取代。
    2. 一直听话认真做完所有作业，毕业时发现「学会的东西 AI 都会做」——像被大学骗了。

    闭环为什么会空心化

    空心化不是「学生偷懒」，而是出题与做题两端都被工具接管后，中间的学习环节失去了强制锻炼。操作系统作业曾是痛苦中的提升来源；现在链接一丢就结束，痛苦消失了，训练也消失了。两种焦虑其实是同一结构的两面：一种是「全对却什么都不会」，一种是「认真学了却发现 AI 都会」。课堂没有给出立刻可执行的自救清单，而是把问题摊开，再在后续课程里给出「先用好、再复盘」的路径。

    简历同质化：信息差与驾驭力

    更现实的压力在简历：课堂展示的「完美简历」有论文与奖项，却没有 GitHub、个人主页或 preprint，讲师判定为零分——你和你的竞争者已经无法区分了。在导师眼里，发表论文可能只是简分项；真正拉开差距的是别人没有的信息差（你有而别人不知道的信息，例如往年试卷这类资源），以及驾驭人工智能的啊能力（讲师原话）：成为能驾驭别人驾驭不了的东西的人。信息差是人类社会进步的必要条件，也是学校里恶性竞争的来源之一；但大学真正该教的是「成为一个更好的人」——能驾驭别人驾驭不了的东西。

    分数本身已不如最后投出的简历重要；但为了走到保研/求职那一刻仍需要较好 GPA，又不得不去 reward hacking（钻考核空子、过拟合考题）——这是教育侧的结构性尴尬。课堂也承认社会上还有许多「不能说的信息差」；好消息是这门课希望缓解焦虑，带大家找回 web coding 的快乐：在做出有趣东西的过程中理解软件工程如何工作，也让简历更好看。

    三、这门课是什么

    (参考时间: 00:07:15–00:09:20)

    课程题目叫生成式软件工程，本质仍是一门软件工程课。软件工程做的事情很简单：怎么样让软件工程不失败——怎样造出一个真正站得住的软件。在 AI 时代，大学更该帮人建立驾驭人工智能的能力。

    信息差、驾驭力与课程形态

    大学真正能给人的，除了信息差，更关键的是「你能做到别人做不到的事」：毕业时你是一个更好的人，拥有别人没有的能力。课程因此定位为帮人建立驾驭 AI 的能力，而不是堆信息差。组织方式偏案例与实践：课上是表演，课后把录像切片、再整理；讲义是 source of truth（唯一权威源），幻灯片与图片全部 AIGC。

    讲师用可复用的流程配置让模型「添油加醋」扩写 slides，每版提示词都重新生成，再在盲评到底哪一个生成的slides的质量比较高之后选定版本——付出更多算力，换取更多智力。课堂自述：即兴意味着不完美，课后把录像重新切片回到 content-as-code（一切内容皆可代码化），实现课程的「数字永生」——讲义可由全世界的人维护、定制（例如定制成某人的操作系统课）。讲课像演员按剧本演出，课后 review 表演、换更贴切的案例。

    课堂还提到：这门课希望能还原「上课耽误学习」的感觉——可以不来课、不看直播，但要在课上实践；录像会切片重整理成可维护的 content。真正想挑战老师观点的同学欢迎线下讨论；只想获取知识的同学，按切片自学即可。

    课程 policy 与评价

    明确 policy 包括：禁止古法编程（以手写每一行、关小黑屋刷题为荣的传统写码方式）；模型调用额度自费（课堂演示多用足够便宜但有智能的模型，如 DeepSeek 系列；幻灯片生成用更强模型求质量；夜里工作模型更便宜——「梁文峰时间」是课堂梗）；考核建议通过/不通过，并给出可选项目（如自建 email 管理系统，跑在宿舍常开小电脑上，与指定邮箱往返通信）。讲师认为分数已不那么重要，真正检验的是投出去的简历能否带你到更高平台；也调侃「如果每人电脑装监控就能评判大学四年」——那会是极其恐怖的社会形态（每条摸鱼痕迹都被看见），保持 open 即可。

    四、从概率到自主循环

    (参考时间: 00:20:32–00:27:40)

    会续写的概率模型

    大语言模型（从海量文本学出「下一个词」概率分布、能续写与对话的模型）就是一个学到的概率分布，和概率课上抛硬币求下次正反面没有本质区别。给它很长的文本，它会按 token（模型读写文本的基本片段，大致对应字/词级单位）不断预测下一个输出。本课站在使用者视角：知道「存在一个东西叫大语言模型」、会打开 API 即可，不必先学模型内部构造。

    课堂用两个例子说明「它不只是文字机器」：一是给五岁孩子解释扫描电子显微镜——GPT-4 打出「闭着眼睛朝山扔石头，听哪些方向穿过去、哪些弹回来，就能推测山形」的比方，讲师事后查资料确认比方成立，自述「第一次被大语言模型按在地上打」；二是同一个 prompt 在 GPT-4 时代要反复调，到更强模型时代变成「一句话的事」。模型见过世界上几乎所有公开知识，训练极难，所以 frontier lab（顶级模型实验室）才有壁垒；但使用者不必先懂训练——打开网页 API 就能体验。

    为何「使用者视角」是课程立场

    模型内部（训练、对齐、推理优化）是另一门课的深度；本课选择站在使用者视角，是因为目标是「把能力用出生产力与好软件」，而不是复现 frontier lab。门槛刻意压低：知道存在大语言模型、会打开 API、能读懂回显，就可以开始模型协作流程。难的是边界判断——什么该交给模型、什么必须人核对——这在后文统分流水线与三个空间里展开。

    工具调用与自主循环

    agent（能输出工具调用、把结果接回上下文并继续试错的智能体）的出现来自上下文变长与推理模型：语言模型可以输出一个特殊 token 去调用程序，程序运行结果送回模型，在 loop 里反复尝试——这样agent就可以自主运行了。配合 ReAct 式流程，错了会换方法，直到任务完成。

    课堂现场配置演示了这条链：窗口管理器提高对比度、去掉顶栏方便上课；top 换成更现代的终端视图；ls 自动换成 eza、find 换成 fd；全部由 agent 配置，讲师只给一句「把命令行终端和系统配置成现代好用的样子」。去年 agent 还常出错停机，今年已能反复改到完成；产品侧也出现大量同类 agent。课堂判断：我认为agent的能力还远远没有被释放出来；next token prediction 可能只是起点，扩散式生成（像做梦一样从噪声逐渐清晰）甚至可回改的长上下文仍在研究中。未来哪条路线胜出无法预测，但世界会变得非常不一样——每个同学都该认真考虑「在这个世界上怎么办」。

    五、算力换智力：怎样把 agent 用出生产力

    (参考时间: 00:10:30–00:15:30)

    讲师的工作流：生成多个 sub-agent（子智能体，各自隔离上下文、被赋予不同性格），主 agent 汇总——通过算力来换智力。原则很简单：现在就开始用、随时问；是你的想象力限制了你的agent的呃上限。课间作业是想「你用 agent 做过最酷的一件事」——想象力是上限。

    学习方式变了

    课程要求禁止古法编程（以手写每一行、关小黑屋刷题为荣的传统写码方式）：AI 时代的学法是你先用好它、把东西做出来，再回头去复盘理解——效率高于从零搭积木，但自己的理解可能和好的理解有差距，需要自觉补课。讲师判断：会用 agent 学习的人和不会的人，他学习的效率差距是十倍100倍。人现在唯一的功能是「带着 AI 做 AI 现在做不到的事」；没有这个能力就会被淘汰。agent 也颠覆了 CS 里「学习曲线太陡、懒得配」的瓶颈：终端配置可以边改边解释，还能提供情绪价值（「token 比学生好用，可以骂他不还嘴」是讲师原话梗）。

    同一套方法也接到日常事务：邮件自动化可以按口吻起草回复、把发票附件自动归档；手机备忘录加一条「打印今天的发票」，后台处理完后经手表推送通知。课堂演示中发票真的打印成功——说明 agent 能操纵真实物理设备，前提是你放心把这些交给它。

    可操作的复盘法：做出东西后，让 agent 把「为什么这样改、失败点在哪」写成笔记，再自己讲一遍给假想学生听；讲不通的地方就是理解缺口。读书读论文同理——先剥离「人类已知」，再盯住真正新增的那一小截。

    风险要一并记下：先做出来再复盘，可能让你停留在「会用但讲不清」；课堂明确说自己的理解可能与好的理解有差距，需要自觉补课。效率差距十倍百倍是讲师判断，不是可复现实验数字。

    用 agent 读书、读论文、消化视频

    同一套方法迁移到学习：把人类已有知识当已知，剥离论文真正新的最少部分，12 页论文往往只剩很短一截；再拿着原文与总结对话。消化两小时视频时，用个人记忆过滤 trivial（已经非常清楚、不必再看）内容，几分钟就能抓住不一样的东西。方法可迁移，但不能代替自己读原文——讲师强调自己仍读论文，不是只刷公众号学习。课堂还展示：给一个 BVID 就能得到图文时间轴与截图密度更大的 ground truth，再交给 agent 消化；对比「十倍百倍效率」的人，同质化简历更可怕。

    从演示到可复用

    装 Linux 到 U 盘、配窗口管理器、改终端：全部由 agent 完成，我没有看过任何一眼配置文件。点睛之笔是点睛之笔是这个用模拟器验证他——要求 agent 自己验证「U 盘能启动、能登录」再交付（课堂细节：agent 在 QEMU 里启动后展示登录界面，再创建用户、给出账号密码）。浏览器同理：chrome dev tools（浏览器自带的开发者调试台）让普通人也能读网络请求、带 cookie 重放；走通一次后我可以把它沉淀成确定性的脚本，形成记忆与可复用流程。课堂演示用浏览器自动填教务周历：模型中途不听指令、走弯路，最后靠注入事件失败、改点鼠标成功——说明能力边界与「session 沉淀」的价值：路径可变成自动抢课/填报脚本。

    生态、skill 组合与飞轮

    skill（用自然语言写的可复用工具/流程配置，可被 agent 安装调用）与脚本可以叠加组合，像 UNIX 管道那样「1+1>2」。典型选型要判断什么东西应该以代码的形式复用、什么东西应该以skill的形式复用。多路信息源（RSS、B 站、arXiv、Hacker News）沉淀成skill或者沉淀成脚本后进入处理系统，持续产出对你有用的知识——你的飞轮就转起来了。课堂判断：agent 生态已到临界点，组合可成百倍放大个人能力；个人 agent 产品（如 OpenClaw 一类）还远不是终极形态。CS 定律（课堂自述）：如果一件事合理且你想做，百分之百也有别人想做——开源与 skill hub 会沉淀可复用能力。

    六、CS 专业视角：边界、流水线与复用形式

    (参考时间: 01:05:18–01:13:30)

    一般人提需求，agent 常常做不好或无法确定性完成；CS 的人知道编程能力的边界，能把需求编译成可复用组件。

    统分流水线：人机边界写进流程

    典型流水线是统分：顶置摄像头拍照 → OCR（把试卷图片里的文字识别成文本）识别姓名学号小分 → 脚本加总 → 语音播报人工核对 → 汇总进教务 Excel。关键约束是我没有让大模型做加法——加法用脚本算，OCR 会错所以人必须核对。课堂口述流程细节：第一阶段双手不写字，一张卷子按一次回车拍照；第二阶段左手回车、右手执笔，语音播报学号与各小分（11+12+…），人核对后把脚本算出的总分抄上卷面；最后自动写入教务 Excel 模板并抽样检查。每一步边界清楚，人和 AI 同步代价最小；即使对最好的模型说「140 张卷子要统分」，也收敛不到这么干净的方案。本地还用 27B 的千问一类模型做识别，减少云端往返。

    受控机与想象力：编码、信道、组件

    另一侧是想象力案例：受控机只能进不能出（金融公司场景），用 Excel 合法公式把文件编成二维码动画「射频」出来；远程桌面上下/左右抖动鼠标编码 0/1，可拼出虚拟网卡。Excel 由 AI 生成，但组件划分（编码、帧、信道）是 CS 知识——上过操作系统与计算机网络，才知道需要哪些组件，才能 web coding 出来。产品同理：产品是一个系统性的工程，前端、后端、交互、运营任一环节做不好都会暴毙；「idea 都有了就差一个程序员」的老梗在 AI 时代仍不成立——组织不好照样暴毙。浏览器本身是软件工程奇迹之一：代码量甚至超过操作系统内核，却为开发者预留了 chrome dev tools 这类接口。

    边界判断：什么给代码、什么给 skill

    CS 视角的核心不是「会写更多代码」，而是能把需求编译成组件，并判断复用形态：确定性计算（加法、汇总、校验）优先代码；流程编排、自然语言判断、文档生成可进 skill；必须对结果负责的环节人要留在环内。统分流水线与二维码案例分别演示了这两侧——前者把人机同步代价压到最小，后者把「合法工具 + 编码知识」组合成系统能力。产品视角同样成立：AI 能做前端后端交互运营中的每一环，但系统组织不好仍会暴毙。

    七、三个空间与 gap：软件工程真正要补的东西

    (参考时间: 01:24:46–01:29:15)

    用 AI 解决问题时存在三个空间：

    空间 含义 课堂例子
    intention（意图：脑子里真正想解决的问题） 老板/甲方真正想要什么 「做一个国民级应用」「点外卖小程序」
    specification（规格：功能、界面、约束的成文约定） 要满足什么要求、有哪些界面 一句「要一个教务系统」下的无数选择
    implementation（实现：具体写出来的代码与系统） 最终写出来的东西 同一规格仍对应大量不同实现

    软件工程它真正的gap就在于这些空间彼此对不齐：甲方只有一句「要一个教务系统」，规格层要做无数选择（界面、表结构、库型……），实现层还会再分叉。经典梗图里客户、产品经理、程序员、宣传各想各的，最后交付物面目全非——根因就是 gap。规格层再展开：界面怎么呈现、数据库 schema 分几张表、选 key-value 还是关系型，每个选择都带来截然不同的结果；实现层哪怕满足同一 spec，仍有大量分叉。软件工程（含生成式软件工程）要做的，就是补上这些 gap。

    gap 不只出现在「说话不清楚」：甲方没有计算机经验时，「要一个教务系统」可能只有这一句 intention；规格层仍要选界面、表结构、主键、库型；实现层还会按团队技术栈再分叉。每层都可能失真，而失真会被杠杆放大。软件工程的方法论（需求、架构、测试、演化、人类学与管理）都是在补这些缝。

    今天的模型靠猜补 gap：模型是猜模型。后训练里任务做对就有奖励，于是他会疯狂的立即上手去尽快完成，像被训练成做题家；它不会先停下来设计结构。软件工程失败的定义没有变：要么意图到规格就错了，要么实现不满足规格（正确性或性能）。传统 CS 学生的路径是先学 implementation 空间里有什么（C 语言、数据结构……），再学软件工程补任务；AI 时代则要同时：阻止模型乱猜，又发挥它从 A 到 B 的能力——这正是本学期要讨论的问题。

    学习路径对照：从实现空间补起 vs 从 gap 补起

    传统路径是先钻 implementation：C 语言、数据结构、系统课，把「有什么零件」摸熟，再上软件工程补任务管理与需求。生成式时代路径变了：既要阻止模型乱猜 gap，又要发挥它从 A 到 B 的高速搬运。课堂强调 gap 在需求端会被杠杆放大——越早的微小偏差，后面越大；大型系统常死在这里，而不是死在某行语法。

    八、为何仍需要生成式软件工程

    (参考时间: 01:17:30–01:38:40)

    第一步不要扩大

    课堂用二维码 Excel 暴毙案例说明：需求一扩大（「任意字符串都要正确」），模型立刻被带歪，写出不可维护的硬编码甚至超长输出。软件工程的第一步不要扩大，做最简单的东西不会失败。受控对照：先做「任意字符串都要对」的大需求时，GPT-5.3 思考约 25 分钟后疯狂输出超过 32K token，直接撞上 output 上限被截断；无人监管跑了约六小时才完成，而且不听指令——用 Python 先算 base64 再贴进公式框，字符串一改编码就不同步。正确路径是先设计中间语言（夹在问题与目标平台之间的小语言/抽象层，便于分别验证与翻译）：XOR、concat 等算子可以同时翻译到 Python 与 Excel；只需分别验证「每个翻译正确」「编码与像素正确」，一把头生成的代码就干净可维护。对照实验里，直接甩大 spec 的模型跑了数小时、硬编码、不听指令。

    中间语言的价值在于「把大问题拆成可分别验证的小翻译」：问题先到小语言，小语言再到 Python/Excel。每个翻译可单独测，编码与像素也可单独测；最后组装时不需要模型一次性「聪明到底」。这与 agent 的 loop 哲学一致——把不可靠的大步，拆成可验证的小步。

    成功侧的细节：让模型设计类似编译器基础设施的 Python 类/算子（XOR、concat 等），既对 Python 友好也对 Excel 友好；只需分别验证「每个翻译正确」「编码与像素正确」，一把头生成的代码就干净、不长且可维护。两份失败产物（不同 roadmap）只要移动工作区位置就要修很久——因为处处硬编码，改一处 validation 就挂。这与教务系统「年年加功能、年年难用」的死法一样：上来就实现需求，陷入维护泥潭，没有为「软件生存几十年」留架构。

    失败会复利

    人月神话（讲大型软件项目像困入焦油坑、加人往往更糟的经典软件工程著作）提醒：项目开始失败时，加人只会更失败。AI 时代同理——你投入更多的token，只会让他变得更失败，模型会在失败产物上继续堆，直到你付不起 token。教务系统年年加功能、年年难用，就是活例子。软件工程同时有技术、人类学、社会学与管理学（管人、离职、跳槽、竞业都是研究对象）；需求端微小偏差会被杠杆放大，大型系统常死在这里。教育侧则是「五分钟题」文化：考场只出短题，训练出的也是做题家；若没有好奇心去练更长周期的问题，最终连解题也不如 AI。

    教育侧的杠杆点：如果考试只出五分钟能解决的题，训练信号就会奖励做题家速度，而不是长周期设计与止损。这与模型被后训练成「尽快交差」是同构问题——人和模型都会在错误的 reward 下变「卷」。课堂没有承诺算法能立刻改教育，但把「练 long horizon 问题」写成了学生的自救方向。

    留给学生的判断

    古法编程已经死了；单个任务上 AI 已无人能敌，但软件工程暂时还没有死。讲师推测 AI 也许能学会好的工程品味（它见过好设计）；也可能三个月后本课内容就过时。收束成保研面试题：「为什么招你，而不是买一个 200 刀的 Claude Max？」模型给出的好答案是——找到值得解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，并对长期结果负责；但模型自己还做不到。
